# Производство игровых ассетов

До производства установи назначение, 2D/3D, камеру, реальный экранный размер,
фон/освещение, набор состояний и доступный потребитель. Сохрани канон игры.
Не выбирай Godot, пиксель-арт, сетку или число кадров только по слову «игровой».

Для 2D договорись о холсте и видимых границах, alpha, pivot/линии опоры,
масштабе, кадрах/длительности и формате. Для пиксель-арта отдельно важны единая
сетка, плотность пикселей и способ масштабирования; увеличенная генерация не
становится корректным пиксель-артом автоматически.
Для 3D нужны единицы, оси, бюджет геометрии/текстур, материалы и требования к ригу
в той мере, в которой они влияют на задачу. Картинка модели не является 3D-файлом.

Референсам назначь роли. Для персонажа прочитай
`character-art-direction`.
Сначала проверь один представительный ассет в контексте; серии производи после
устранения общей ошибки масштаба/стиля. Для уже согласованной серии сразу соблюдай
её контракт. Генератор не гарантирует точный холст, pivot или выравнивание кадров.

Посмотри силуэт, контраст с игровым фоном, различимость ролей, края alpha и
согласованность серии в реальном игровом размере. Для анимации проверь линию
опоры, дрожание, переходы и петлю; для 3D — также материалы, ориентацию и контакт.
Для проверки растра используй [анализатор](scripts/inspect_asset.py) с Python и Pillow.
Запускай `python <путь-к-анализатору> <файл>`. Добавляй `--size WxH` и
`--require-transparency`, когда эти требования заданы в брифе.
Проверка alpha не обнаруживает нарисованную шахматную подложку.

Для подтверждённого Godot используй
`godot-assets-pipeline`
и профиль игры. Для другого движка найди его действующий процесс и документацию.
Без потребителя пометь runtime-проверку как не выполненную.

Передавай исходник, экспорт и применимые данные из
[манифеста](references/asset-manifest-template.json), включая происхождение.
Не называй сведённый PNG редактируемым многослойным источником. Сообщи отдельно
художественную оценку, проверку файлов и подтверждённую интеграцию.
