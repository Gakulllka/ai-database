# Универсальная дизайн-база

Используй текущий бриф, исходники и канон. Определи носитель, аудиторию,
нужное восприятие/действие, конечный масштаб, сохраняемые свойства и доказательство
готовности. Не навязывай один стиль и не начинай повторное интервью для локальной правки.

Прочитай [карту процессов](references/workflows.md) и проверь, какие инструменты доступны для задачи.

| Задача | Владелец |
| --- | --- |
| Арт в принятом стиле «Грязный хоррор» | [dirty-horror](../dirty-horror/SKILL.md) + владелец производства |
| Создать новый или усилить существующий визуальный стиль | [visual-style-development](../visual-style-development/SKILL.md) |
| Персонаж и иллюстрация | `character-art-direction` |
| Интерфейс | `frontend-design-direction`, для рабочего инструмента его `references/functional-ux.md` |
| Веб-система и токены | `design-system` |
| Поддержка принятого канона между продуктами | `ecosystem-design-consistency` |
| Игровой ассет | [game-art-production](../game-art-production/SKILL.md) |
| Арт новеллы | [visual-novel-art](../visual-novel-art/SKILL.md) |
| Разбор | [visual-quality-review](../visual-quality-review/SKILL.md) |
| Упражнение | [visual-design-practice](../visual-design-practice/SKILL.md) |

Для бренда, видео и 3D выбери существующего владельца из каталога, прочитай его
инструкцию и проверь среду. Присутствие рецепта не означает доступ к программе.

Растр производи доступным инструментом генерации/редактирования и его навыком;
существующий редактируемый вектор или код сохраняй в подходящем родном процессе.
Для нового направления полезен поиск существенно разных вариантов; принятый
канон позволяет сразу выполнять задачу. Не создавай дополнительный style pack,
turnaround или приложение, если результат этого не требует.

Заверши просмотром реального результата в целевом контексте и техническими
проверками нужного формата. Отдельно сообщи, что осталось только концептом,
что проверено как файл и что действительно запускалось в потребителе.
