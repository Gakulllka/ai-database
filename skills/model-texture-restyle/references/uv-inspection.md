# Самостоятельное чтение модели и UV

## Что установить из файлов

Запиши фактическую цепочку для каждой редактируемой карты:

`объект / грани → материал → канал → изображение → UV-слой → преобразование / wrap`

Нужен используемый материалом UV-слой, а не только активный в редакторе. Одна
картинка может обслуживать несколько материалов с разными координатами; один
материал может использовать разные UV для разных каналов. Встроенные и внешние
картинки сопоставляй по реальным ссылкам/содержимому, не только имени файла.
Отдельно выявляй vertex color, процедурные узлы, проекцию без UV и недостающие
карты: они могут объяснять отличие вида от плоской текстуры.

Проверь координаты за пределами 0–1, режим повторения/зажима, UV-transform и
UDIM, если они присутствуют. Не своди неподдержанную схему к обычному атласу
молча. При неполном импорте укажи, какие данные потеряны и какие выводы ненадёжны.

## Как находить общие области

Оверлап имеет смысл в пространстве реально выбираемых пикселей конкретной
карты/плитки. Одинаковые UV у разных независимых текстур не являются конфликтом
между этими текстурами. Разные материалы с одним изображением, напротив, могут
изменяться одновременно. Учитывай преобразования и повторение координат.

Различай:

- Полностью совмещённые поверхности, включая повторное использование одного
  острова несколькими частями. Границы могут быть разбиты на разные треугольники:
  равенство списков UV-вершин не является исчерпывающей проверкой.
- Частичные наложения положительной площади: часть рисунка общая, часть нет.
- Зеркальное использование. Его подтверждают соответствие поверхностей и
  направление диагностического рисунка на модели; одна ориентация UV-треугольника
  без учёта граней и трансформаций недостаточна для семантического вывода.
- Соседние грани с общей кромкой. Касание по ребру/вершине не считай наложением
  площади. Близость островов и пересечение их padding — отдельный риск фильтрации.
- Вырожденные UV, общую полоску/точку цвета, очень маленькие острова. Это может
  быть сознательная оптимизация; не расширяй и не «исправляй» её автоматически.

Запиши метод проверки и точность. Растровая карта покрытия полезна для
диагностики, но её разрешение может скрыть субпиксельные пересечения; не называй
её точным доказательством их отсутствия. При невозможности учесть wrap/узлы
ограничь утверждение поддержанными материалами и участками.

Для одного изображения сведи покрытие всех обращений через материалы/каналы,
а не только острова одного UV-слоя. В glTF учитывай исходный texCoord и его
возможное переопределение в KHR_texture_transform до анализа transform/wrap.
Совмещение в неиспользуемом слое само по себе не ограничивает целевую правку.

Для каждой группы общего использования перечисли все найденные поверхности и
влияние правки. Поверхности вне текущего ракурса тоже являются потребителями.
Разная индивидуальная деталь на общем пикселе требует изменения схемы UV/материала
пользователем либо компромисса рисунка; текстурный генератор этого не устраняет.

## Как установить, где находится остров

Сделай техническую ID-карту с уникальными цветами, номерами и при необходимости
несимметричными стрелками/буквами. Это диагностический инструмент, не финальный
арт; его можно строить кодом в рамках доступных средств. Назначай карту только
в диагностической копии, сохраняя тот же UV-слой/преобразование, что у цели.

Посмотри перед, зад и бока, крупно лицо/предметные детали. Скрытые части
рассмотри изолированно; изменённую диагностическую видимость не выдавай за вид
исходной модели. При нужде визуализируй грани/ID непосредственно, если надписи
на маленьких UV не читаются. Для общего UV одинаковый цвет сам по себе не
показывает, какой из потребителей первый: перечисли все поверхности.

Сопоставляй с исходной текстурой и формой. Названия объектов помогают, но не
заменяют наблюдение. Не объявляй «затылком» неизвестную грань только из-за её
маленькой площади. Спрятанное в одной позе не означает невидимое в игре;
возможную анимацию или смену камеры нельзя восстановить из статичного файла.

## Короткая запись результата

В project/reviews/uv-inspection.md или аналогичном отчёте достаточно:

| Поле | Содержание |
| --- | --- |
| Источник | Файл/хеш, импортёр/версия, ограничения чтения |
| Целевая карта | Материал/канал, изображение/размер, UV-слой, transform/wrap |
| Область | Стабильный в рамках данной версии ID, объект/грани, виды модели |
| Назначение | Наблюдаемая поверхность; уверенность и основание |
| Общий UV | Потребители, полное/частичное/зеркальное использование, метод |
| Риски | Размер, швы, альфа, отсутствующие данные, конфликт желаемого рисунка |
| Вопрос | Только решение, которое существенно меняет результат и не выводится из файла |

Добавь читаемую карту островов и связанные виды. Не присваивай результату
«проверено», если карта лишь построена, но не была просмотрена на модели.
При новой версии модели переустанови соответствия: старые номера граней/островов
могли измениться. Известные ответы пользователя переноси с проверкой привязки.

Если исходный формат недоступен, попроси минимальный проверяемый экспорт модели
с нужными UV-слоями, назначениями материалов и картами. Проверь сохранение
существенных преобразований и узлов: любой GLB не является автоматически полным
эквивалентом BLEND. Картинка UV и обычный скриншот не заменяют эти связи.

Справка по возможному инструменту: [Blender UV selection / Select Overlap](https://docs.blender.org/manual/en/4.5/editors/uv/selecting.html).
Команда выделения — вспомогательный инструмент; семантику материалов и намерение
пользователя она сама не устанавливает. Сверяй поведение с установленной версией.
