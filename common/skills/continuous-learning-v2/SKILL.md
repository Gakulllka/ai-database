# Continuous Learning v2

Review a bounded part of completed work on request. Produce one small lesson per trigger and action. Start in the current project's permitted scope.

1. Inspect the actual correction, test result, output or minimal redacted trace excerpt. Label the evidence as direct observation, user preference, or inference. Keep enough of the source, revision, date and result for another reader to reproduce the conclusion.
2. Look for a rule that already covers the case. Update or link that rule when the new case adds evidence. Record conflicting examples and distinguish a broken requirement from an intentional exception.
3. State the condition before the action. Add a limit or counterexample when applying the rule broadly would change unrelated work. Assign a confidence level from the evidence anchors in the [reviewed lesson format](references/reviewed-lesson.md).
4. Return a draft unless the user requested saving or an existing project instruction authorizes it. Use the project's selected lesson store and its actual project ID. A learned preference belongs to the project where it was observed.
5. Revisit the lesson after a new result. To promote it to a shared rule or skill, verify it on a meaningfully different task, confirm the intended scope, and use [learn-eval](../learn-eval/SKILL.md).

The Codex workflow uses selected evidence and deliberate saves. Background observation, legacy instincts tooling and migration of old stores require their own explicit setup and verification.
