# От запроса к проверенному результату

## Общий ход

Для новой работы зафиксируй носитель, аудиторию, эффект/действие, обязательное,
сохраняемое и формат передачи. Используй [бриф](brief-template.md) соразмерно
задаче: точечная правка может иметь бриф в несколько строк.

Референсам назначь роли: образ, стиль, композиция, палитра/материал, поза или
антипример. Сохрани ссылки и права. Нельзя автоматически переносить все свойства
одного референса. Затем выбери процесс по таблице ниже.

Если направление не решено, сравни несколько существенно разных подходов в
одинаковой подаче. Если канон уже принят, сразу выполняй задачу в нём. Число
вариантов и корректировок должно соответствовать задаче и доступному бюджету.

Перед финалом посмотри результат в его реальном масштабе, проверь файлы и,
если это входит в задачу, приложение-потребитель. Сохрани [разбор](../../visual-quality-review/references/review-template.md)
с выводом о следующем изменении или готовности.

## Ветки

| Запрос | Ведущий процесс | Что означает готовность |
| --- | --- | --- |
| «Нарисуй в нашем грязном хорроре» | [dirty-horror](../../dirty-horror/SKILL.md) + профильный арт-процесс | Рисовка по якорям, нейтральная основа и единственный яркий красный; проверка реального результата |
| «Создадим стиль / усилим существующий» | [visual-style-development](../../visual-style-development/SKILL.md) | Создание: согласованный пак → тесты → принятый стиль как навык. Усиление: диагностика → сравнимая проба → проверка эффекта → принятые изменения |
| «Нарисуй персонажа» | character-art-direction + доступный imagegen | Увиденный арт с сохранёнными признаками и целевым кадром |
| «Сделай спрайт / набор предметов» | game-art-production | Экспорт по контракту и просмотр в масштабе игры; интеграция подтверждается отдельно |
| «Сделай арты для новеллы» | visual-novel-art + character-art-direction | Согласованная серия и составленный кадр диалога |
| «Почему это выглядит плохо?» | visual-quality-review | Видимые причины, приоритеты, конкретные правки и пределы уверенности |
| «Сделай интерфейс» | frontend-design-direction или UI-владелец платформы | Реальный рендер, сценарий, текст и состояния |
| «Собери бренд» | Бриф о продукте, аудитории и желаемом образе, затем профильный визуальный процесс | Согласованный бриф и канон с примерами на нужных носителях |
| «Сделай видео» | video-editing / Remotion / Manim по задаче | Просмотрен точный экспорт, проверены звук и длительность, если применимы |
| «Сделай 3D» | Профильный Blender/engine workflow после проверки среды | Редактируемый источник и проверенный экспорт; картинка модели не заменяет геометрию |
| «Хочу прокачаться» | visual-design-practice | Упражнение, версия до/после, объяснение изменения и перенос на новый пример |

Это карта выбора, а не обещание готового инструмента для каждого носителя.
Перед производством проверь, какие инструменты доступны в текущей среде.

## Хранение

Создавай каталоги по мере использования:

```text
projects/<имя>/
  brief.md
  style-guide.md
  references/   — ссылки, заметки, разрешённые локальные референсы
  source/       — редактируемые оригиналы
  exports/      — производные файлы для передачи
  reviews/      — наблюдения и сравнения версий
  asset-manifest.json
```

Имена вариантов должны различать версии и назначение. Не называй генерацию
со слоями, если есть только сведённое изображение. Манифест должен отделять
человеческое одобрение, техническую проверку и запуск в потребителе.
