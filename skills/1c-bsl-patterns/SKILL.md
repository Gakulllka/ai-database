# 1C / BSL Development Patterns

## When to Activate

- Изменение модулей управляемой формы, объекта, менеджера или общего модуля 1С.
- Ошибки клиент-серверного контекста, запросов, записи, транзакций или прав доступа.
- Ревью BSL и использования встроенной БСП.

Для XML-структур и применения конфигурации начни с
[1c-development](../1c-development/SKILL.md). Для самостоятельного OneScript сначала
проверь его среду: наличие `.os` не подтверждает доступность API платформы 1С.

## Establish the actual environment

Установи версию платформы и режим совместимости, вид клиента, свойства модуля,
версию встроенной БСП, происхождение и свежесть выгрузки. Используй синтакс-помощник
целевой платформы и документацию именно доступной версии API. При неполных данных
помечай допущение и проверку, которую ещё требуется выполнить.

Читай [правила 1С](../../rules/1c/patterns.md) и подходящий первичный источник из
[справочника источников](references/sources.md) по спорному вопросу.

## Execution context

В модуле управляемой формы:

| Контекст | Назначение |
|---|---|
| `&НаКлиенте` | Пользовательское взаимодействие и доступные клиенту операции |
| `&НаСервере` | Серверная операция с данными формы |
| `&НаСервереБезКонтекста` | Серверная операция без доступа к данным формы, с явными параметрами |

Для общего модуля учитывай его свойства и экспорт; не переноси в него директивы
формы механически. Сверяй доступность вызываемого API и передачу типов значений
для нужного клиента. Клиентские пути файлов не обозначают те же файлы на сервере.
Объединяй связанные обращения к серверу вместо вызова на каждую строку.

## Mutable objects and persistence

Ссылку, изменяемый прикладной объект, набор записей и данные формы различай явно.
Штатное изменение объекта или табличной части допустимо: это языковое уточнение
общего предпочтения immutability. Сохраняй владельца изменения и видимость побочных
эффектов. Получение объекта, изменение его реквизитов и `Записать()` — разные действия;
не добавляй запись или проведение как скрытое следствие чтения.

## Parameterized queries

Передавай значения через `УстановитьПараметр`, а динамические идентификаторы проверяй
по метаданным. Определи требуемую полноту результата и политику RLS: автоматическое
добавление `РАЗРЕШЕННЫЕ` может изменить смысл итогового расчёта.

Пример для модуля управляемой формы конфигурации, где существует справочник
`Номенклатура`. Имена метаданных и тип параметра адаптируются к проекту.

<!-- markdownlint-disable MD010 -->
```bsl
&НаСервереБезКонтекста
Функция НаименованиеПоСсылке(СсылкаНоменклатуры)

	Запрос = Новый Запрос;
	Запрос.Текст =
		"ВЫБРАТЬ
		| Номенклатура.Наименование КАК Наименование
		|ИЗ
		| Справочник.Номенклатура КАК Номенклатура
		|ГДЕ
		| Номенклатура.Ссылка = &Ссылка";
	Запрос.УстановитьПараметр("Ссылка", СсылкаНоменклатуры);
	Выборка = Запрос.Выполнить().Выбрать();
	Если Выборка.Следующий() Тогда
		Возврат Выборка.Наименование;
	КонецЕсли;
	Возврат Неопределено;

КонецФункции
```
<!-- markdownlint-enable MD010 -->

Не подставляй дату примера в запрос как бизнес-правило. Вычисляй границы периода
по согласованной семантике и передавай их параметрами.

## Transactions and exceptions

Сначала выясни, существует ли транзакция платформы или вызывающего кода. В частности,
запись и проведение могут задавать неявную транзакцию. Дополнительный вызов начала
не создаёт независимую вложенную единицу сохранения.

Шаблон для процедуры, владеющей собственной явной транзакцией и атомарной записью
небольшого подготовленного набора объектов в разрешённой среде:

<!-- markdownlint-disable MD010 -->
```bsl
НачатьТранзакцию();
Попытка
	Для Каждого ОбъектЗаписи Из ОбъектыЗаписи Цикл
		ОбъектЗаписи.Записать();
	КонецЦикла;
	ЗафиксироватьТранзакцию();
Исключение
	ОтменитьТранзакцию();
	ВызватьИсключение;
КонецПопытки;
```
<!-- markdownlint-enable MD010 -->

Это схема обработки ошибки, не готовая массовая обработка. Для конкурентной операции
проверь режим блокировок, актуальность читаемых значений и нужный набор защищаемых
данных. Сохраняй атомарность без ожидания пользователя или длительного внешнего вызова
в транзакции. Не маскируй исключение пустым обработчиком; сохраняй диагностическую
информацию по принятому в проекте механизму с исключением секретов.

## Compatibility and security

Используй публичные возможности реально встроенной БСП. Наличие метода в другой
версии библиотеки не подтверждает его наличие здесь. Сохраняй существующие контракты
обработчиков и проверь способ доработки типового решения.

Проверяй вход и права на серверной границе. Не устраняй ошибку прав включением
привилегированного режима или ослаблением RLS. Для существующего доверенного
привилегированного участка проверь его назначение и границы.

## Verification and delivery

Примеры выше написаны для объяснения паттернов и не проходили синтаксическую проверку
целевой платформой. Используй настроенные статические диагностики и проверки проекта,
затем доступную синтаксическую/функциональную проверку через
[1c-testing](../1c-testing/SKILL.md). Для расчётов проверь период, пустые данные и повторное
выполнение. Для прав — нужные роли, для конкурентной записи — многосеансовый сценарий.

В отчёте разделяй изменённые исходники, применение конфигурации и обновление ИБ.
Укажи версию и среду выполненных проверок, их результат и оставшиеся зависимости.

## Anti-Patterns

- API платформы на клиенте или в OneScript без проверки его доступности.
- Серверный вызов и запрос внутри каждого шага большого цикла без причины.
- Конкатенация пользовательских значений с текстом запроса.
- Пустой `Исключение`, успех после ошибки или фиксация транзакции чужого владельца.
- Ослабление доступа ради прохождения проверки или неподтверждённая совместимость БСП.
- Вывод о корректности расчёта по открытию формы или о состоянии ИБ по локальному diff.
