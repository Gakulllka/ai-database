# Инструкции проекта 1С

## Общая Database

В начале каждой новой сессии и после потери контекста прочитай:

1. `C:/AI/Database/AGENTS.md` и общие правила `C:/AI/Database/rules/common/`.
2. `C:/AI/Database/rules/1c/` и `C:/AI/Database/skills/1c-development/SKILL.md`.
3. Подходящие навыки из актуального `C:/AI/Database/skills/`, включая
   `1c-bsl-patterns` для кода, `1c-testing` для проверки и тематический навык операции.

Используй актуальные материалы по указанным путям. Новые личные навыки и роли
участвуют в поиске вместе с исходными материалами ECC. Общие инструкции остаются
в Database, здесь фиксируются особенности проекта. При недоступности базы сообщи
об этом и запроси доступ; отметь непроверенное подключение.

Проверяй свежесть Database по приватному `origin` и официальному ECC `upstream`
согласно `C:/AI/Database/docs/database-sync.md`. Fetch выполняй в Database;
обновление её рабочих файлов относится к задаче сопровождения общей базы.
Недоступный источник отмечай как непроверенный.

## Контекст проекта

Версия платформы, режим совместимости, конфигурация, БСП и авторитетный каталог
исходников пока не определены. Установи их по файлам проекта и решениям пользователя
и замени эту секцию подтверждёнными сведениями. Актуальность выгрузки проверяется
отдельно от состояния подключённой информационной базы.

Проектные правила имён и маркировки изменений пока не заданы. Следуй существующим
конвенциям и ECC; не вводи `_ЕМК` или специальные комментарии автоматически.

## Типовые механизмы и понятный код

До добавления логики найди существующий механизм и проследи его вызовы, включая
подписки, формы и расширения. Сначала оцени применимость типового решения и
публичного API встроенной БСП в фактической версии. Исправляй ответственный участок,
проверяй оставшийся старый код и повторные вызовы после замены. Совместимость и
необходимость сохранённых адаптеров объясняй явно.

Существенные бизнес-правила и ожидаемый результат определяет пользователь.
Примеры хорошего и плохого кода используй для выяснения требований к поддержке;
не объявляй их отдельные приёмы универсальными. При изучении проекта сначала
построй карту механизмов, затем читай связанные реализации по задаче.

## Изменения и проверка

Готовь изменения в исходниках в рамках порученной задачи. Загрузка конфигурации,
обновление ИБ и изменение бизнес-данных — отдельные действия с конкретной целью
и разрешённой средой. Поддержку типовых объектов и API встроенной БСП учитывай
до изменения. Примеры дат и сумм не превращай в константы бизнес-логики.

Команды сборки, анализа BSL, синтаксической и функциональной проверки пока не
определены. Запиши реальные команды и рабочие каталоги после изучения среды.
Разделяй структурную проверку, smoke и проверку расчётов; сообщай только фактически
выполненные действия. При необходимости используй роли `1c-reviewer` и
`1c-build-resolver` из Database через доступный механизм делегирования.

## Локальные данные

Подключения и учётные данные храни вне отслеживаемых файлов.
До создания `.v8-project.json` настрой его локальное игнорирование.
При использовании веб-помощников рабочий каталог — корень этого проекта;
состояние браузера находится в `.scratch/1c-web-client/` и не включается в Git.
Git не заменяет резервную копию ИБ.
