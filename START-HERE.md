# Новый проект с Database

Обновлено: 2026-11-07.

`C:\AI\Database` — общая база всех моих проектов. Её основа — ECC;
мои навыки и агенты добавляются в те же `skills/` и `agents/`.
Проект хранит собственные особенности, а общие правила получает из Database.

## Откуда скачать и как обновлять

Основной источник — приватный
[Gakulllka/ai-database](https://github.com/Gakulllka/ai-database), ветка `database`.
Он содержит ECC и личные дополнения. Официальный ECC остаётся отдельным `upstream`.
При первом запуске на другом ПК и в начале сессий проверяй обновления **обоих**
репозиториев по [инструкции синхронизации](docs/database-sync.md).
Проверка свежести не выполняет автоматическое объединение рабочих файлов.

## Что написать в новом проекте

> Прочитай `C:\AI\Database\START-HERE.md`, изучи Database и текущий проект.
> Используй Database как общую основу правил, навыков и агентов.
> Создай в корне проекта готовый `AGENTS.md` по этой инструкции.
> Если он уже существует, аккуратно дополни его, сохранив действующие указания.

## Инструкция агенту

1. **Изучи проект.** Прочитай существующие `AGENTS.md`, `AGENTS.override.md`,
   README, манифесты, команды и конфигурацию CI. Определи назначение, стек,
   структуру и доступные проверки по реальным файлам и словам пользователя.
2. **Изучи общую основу.** Прочитай [AGENTS.md](AGENTS.md),
   [описание правил](rules/README.md) и файлы в [rules/common/](rules/common/).
   Общие принципы ECC применяются к проекту. Пути, команды сборки и процедуры
   сопровождения самого ECC относятся к Database; команды проекта определяй отдельно.
3. **Подбери материалы.** Посмотри актуальный состав `rules/`, `skills/` и `agents/`.
   По именам и описаниям выбери материалы для стека и задач проекта, затем прочитай
   подходящие правила, `SKILL.md` и инструкции ролей. Личные дополнения участвуют
   в том же поиске. Полные тексты всех навыков загружать для каждой задачи не нужно.
4. **Создай проектный файл.** Возьми
   [основу AGENTS.md](examples/database-project-AGENTS.md) и заполни её фактами
   проекта. Существующий файл дополни без потери полезных инструкций.
   Если корневой `AGENTS.override.md` замещает `AGENTS.md`, сохрани его указания
   и добавь подключение Database также в действующий override.
5. **Проверь результат.** Проверь пути к выбранным материалам и источники команд.
   Итоговый `AGENTS.md` должен быть рабочей инструкцией, без незаполненных шаблонов
   и выдуманных возможностей. Сообщи путь к нему и какие материалы подключены.

## Что должно быть в проектном AGENTS.md

- Абсолютный путь `C:/AI/Database` и явное требование читать общую базу
  при каждой новой сессии и после потери контекста.
- Порядок применения общих правил и выбора актуальных навыков и агентов.
- Назначение проекта, подтверждённый стек и важные каталоги.
- Реальные команды установки, запуска, сборки и проверок с рабочими каталогами,
  если они уже определены; источник каждой команды должен существовать.
- Ссылки на подходящие каталоги правил, навыки и роли в Database.
- Особенности проекта и существующие локальные ограничения.
- Проверку свежести общей Database по `origin` и `upstream` согласно
  `C:/AI/Database/docs/database-sync.md`; при другом пути адаптируй ссылку.

Если папка проекта пустая, создай минимальный готовый файл с подключением Database.
Запиши, что стек и команды ещё не определены; дополняй их по мере появления файлов
и решений пользователя. Для существующей инфраструктуры замени этот текст фактами.

Для проекта 1С дополнительно прочитай
[1c-development](skills/1c-development/SKILL.md) и [правила 1С](rules/1c/).
Используй [проектную основу 1С](examples/1c-project-AGENTS.md) вместо общей,
подтверди версии платформы/БСП, формат и свежесть исходников и целевую среду.
Доступные направления перечислены в [руководстве 1С](docs/1c/README.md).

Для проекта Godot найди предназначенный для работы `project.godot` (он может
находиться во вложенном каталоге). Прочитай
[godot-development](skills/godot-development/SKILL.md) и [правила Godot](rules/godot/),
используй [проектную основу Godot](examples/godot-project-AGENTS.md).
Подтверди версию/тип движка, язык/SDK, 2D/3D, renderer, платформы и доступные
проверки. Направления описаны в [руководстве Godot](docs/godot/README.md).

## Как использовать общую базу дальше

Для накопления переносимого опыта и регулярного улучшения базы прочитай
[database-evolution](skills/database-evolution/SKILL.md) и
[инструкцию бота](docs/design/database-evolution.md). В конце существенной задачи
проверь, есть ли подтверждённый общий урок, которого ещё нет в Database; подготовь
очищенное предложение по этому процессу. Частные бизнес-правила остаются в проекте.
На новом ПК отдельно подключи локальное расписание Codex по инструкции; Git
переносит процесс и знания, но не регистрацию задания приложения.

Для задач согласованности дизайна нескольких продуктов, локально-серверной
синхронизации, импорта таблиц и ИИ-артефактов учитывай
[навыки, извлечённые из DELTA](docs/delta/README.md).
Они выбираются по задаче и не подключают бренд или настройки DELTA автоматически.

Проектный `AGENTS.md` хранит ссылки и местные особенности. Общие правила и тексты
навыков остаются в Database и перечитываются в актуальном виде. Перед выбором
материалов учитывай новые файлы в `skills/`, `agents/` и `rules/`, даже если их ещё
нет в списке рекомендаций проекта. При изменении стека обновляй проектные ссылки.

Явные указания пользователя и ограничения среды имеют приоритет. Локальные
инструкции уточняют общую основу применительно к проекту; существенные противоречия
обозначай пользователю, сохраняя уже действующие указания.

Во время работы над отдельным проектом Database используется для чтения.
Проверка обновлений через fetch в самой Database описана в инструкции синхронизации;
она изменяет только служебные Git refs, а не рабочие файлы.
Добавление или изменение общих материалов выполняется по поручению пользователя.
Если Database недоступна, сообщи об этом и запроси доступ; продолжай только
независимую работу и явно укажи, что подключение общей базы пока не проверено.

## Особенности Codex и других приложений

Путь в Markdown сам по себе не загружает внешний файл. Проектный `AGENTS.md`
должен прямо поручать агенту прочитать указанные материалы. Подключение Database
считается проверенным после фактического чтения этих файлов в сессии проекта.

`SKILL.md` можно прочитать как рабочую инструкцию. Файл в `agents/` описывает роль,
но сам по себе не регистрирует инструмент или подагента: используй доступный
механизм делегирования, а при его отсутствии выполни применимые шаги самостоятельно.
Конфигурации MCP, хуки и настройки приложений требуют отдельного подключения;
создание проектного `AGENTS.md` не означает, что они установлены или запущены.
