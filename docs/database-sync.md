# Получение и обновление общей Database

Основной репозиторий: [Gakulllka/ai-database](https://github.com/Gakulllka/ai-database)
(private), рабочая ветка `database`.
Основа ECC: [affaan-m/ECC](https://github.com/affaan-m/ECC), ветка `main`.

## Два источника

| Remote | Назначение | Как используется |
|---|---|---|
| `origin` | Наш приватный репозиторий: ECC и личные навыки, агенты, правила | Основной источник клонирования, обмена между ПК и публикации дополнений |
| `upstream` | Официальный ECC | Получение изменений для последующего объединения с нашей веткой |

Новый ПК получает Database из `origin`. Клонирование только ECC не переносит
наши дополнения. Клонирование сохраняет `origin`; `upstream` на каждом новом ПК
добавляется отдельно. Для приватного репозитория нужен доступ к аккаунту GitHub;
используй настроенную авторизацию Git, не вставляй токен в URL.

## Первый запуск на другом ПК

Команды ниже рассчитаны на ещё не существующий каталог `C:/AI/Database`:

```powershell
git clone --branch database https://github.com/Gakulllka/ai-database.git C:/AI/Database
git -C C:/AI/Database remote add upstream https://github.com/affaan-m/ECC.git
git -C C:/AI/Database remote set-url --push upstream DISABLED
git -C C:/AI/Database config remote.pushDefault origin
git -C C:/AI/Database config branch.database.pushRemote origin
git -C C:/AI/Database fetch upstream --prune
```

Если Database уже есть, сначала проверь `git status`, ветку и `git remote -v`.
Не клонируй поверх существующего каталога и не заменяй его рабочие файлы.
Добавляй отсутствующий remote; неожиданное значение существующего разбери до
изменения. `DISABLED` оставляет получение ECC доступным и блокирует отправку туда.

После загрузки прочитай [START-HERE.md](../START-HERE.md). При другом пути сохрани
этот реальный путь в проектных `AGENTS.md`. Перенос Git-файлов не устанавливает
платформу 1С, Godot, SDK, зависимости, MCP или настройки приложения; их доступность
проверяется отдельно на выбранном ПК.

## Проверка свежести в начале сессии

При начале работы и подключении нового проекта проверь **оба** источника.
Команды выполняются в Database, а не в Git-репозитории проекта-потребителя:

```powershell
git -C C:/AI/Database fetch origin --prune
git -C C:/AI/Database fetch upstream --prune
git -C C:/AI/Database rev-list --left-right --count database...origin/database
git -C C:/AI/Database rev-list --count database..upstream/main
```

В первом результате `rev-list` слева — только локальные коммиты, справа — только
коммиты `origin/database`. Второй результат показывает ещё не вошедшие в нашу ветку
коммиты ECC. При ошибке fetch не называй старые remote-tracking refs актуальной
проверкой сервера. Отметь недоступный источник и продолжай независимую работу
с имеющимися инструкциями.

Fetch обновляет служебные Git refs, не объединяет код и не меняет рабочие файлы.
Во время работы над проектом-потребителем разрешена такая проверка свежести;
обновление рабочих файлов общей Database выполняется задачей её сопровождения.
Сообщай о найденных обновлениях, не подменяя одновременно инструкции работающих
проектов автоматическим merge.

## Получение изменений нашего репозитория

В задаче обновления проверь отсутствие незавершённых операций Git и локальных
изменений, затем используй:

```powershell
git -C C:/AI/Database switch database
git -C C:/AI/Database pull --ff-only origin database
```

При локальных изменениях или разошедшейся истории сначала сохрани и разбери их.
Не применяй `reset --hard`, очистку файлов, автоматический stash или force push
как способ убрать конфликт. Объединение должно сохранять работу с обоих ПК.

## Получение изменений ECC

Сначала получи изменения `origin`, затем в чистой рабочей ветке `database`
просмотри разницу с обновлённым `upstream/main` и выполни объединение в рамках
задачи сопровождения:

```powershell
git -C C:/AI/Database fetch upstream --prune
git -C C:/AI/Database log --oneline database..upstream/main
git -C C:/AI/Database merge upstream/main
```

Разрешай конфликты с сохранением личных скиллов, правил, агентов и инструкций
подключения. История ECC сохраняется; смена `origin` на ECC или замена нашей ветки
официальной веткой не являются обновлением Database.

После изменений навыков синхронизируй затронутые проекции:

```powershell
node scripts/1c/sync-skills.js --write
node scripts/godot/sync-skills.js --write
node scripts/delta/sync-skills.js --write
```

Выполняй только команды нужных наборов. Проверь соответствие проекций, метаданные,
каталог, ссылки и затронутые проверки проекта. Команды запускаются из Database;
зависимости валидаторов должны быть установлены. Недоступную проверку отмечай
явно. Обновление библиотеки инструкций не доказывает работу 1С или игры.

Проверенный результат сохрани коммитом. Отправка в `origin` выполняется в рамках
поручения на публикацию; проверка обновлений сама по себе не поручает push.
Отправлять наши изменения в `upstream` не нужно.

## Что хранится в Git

В репозитории находятся ECC и наши общие дополнения. Временные проверки,
`node_modules`, логи и рабочие результаты остаются вне Git согласно `.gitignore`.
Кодовые базы DELTA и GameDev, исходный ZIP 1С и пользовательские информационные
базы не являются содержимым Database. Локальные подключения, пароли, токены и
данные сессий хранятся отдельно.

Унаследованные workflow ECC остаются в истории. При первой публикации GitHub
Actions в нашем репозитории отключаются; подключение конкретной автоматизации
выполняется отдельно после разбора её действий.
