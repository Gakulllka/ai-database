# Поддержка 1С в Database

Обновлено: 2026-11-07. Основа организации — ECC; предметные материалы адаптированы
из пользовательского `Codex_1C_Workspace_v3.zip`.

## Начало работы

В новом проекте попроси агента прочитать `C:/AI/Database/START-HERE.md` и создать
проектный `AGENTS.md`. Для проекта 1С он дополнительно читает
[1c-development](../../skills/1c-development/SKILL.md),
[правила 1С](../../rules/1c/) и выбирает тематический навык по задаче.
Пример: [1c-project-AGENTS.md](../../examples/1c-project-AGENTS.md).

Общие правила ECC продолжают действовать. Языковые уточнения находятся в `rules/1c/`;
например, штатное изменение прикладного объекта 1С допустимо и не требует создания
искусственной неизменяемой копии. Проект задаёт свои имена, версии и команды.

В [правилах паттернов](../../rules/1c/patterns.md) закреплён поиск действующего
механизма до добавления нового и проверка старых путей после замены. Ревьюер
проверяет дублирование и понятность ручного сопровождения. Типовые решения и ИТС
сверяются с версией проекта; недостающие бизнес-правила определяет пользователь.

## Инструменты и окружение

Операции перечислены в
[operations.json](../../skills/1c-platform-tools/operations.json).
Прежние узкие навыки стали адресными `operation.md` внутри общего набора ресурсов.
Они не добавляют 81 независимую команду в меню и сами не запускаются.
Расположение операций сохранено соседним, чтобы внутренние вызовы валидаторов
продолжали разрешаться.

После изменения канонических `skills/1c-*` обнови копии Codex командой
`node scripts/1c/sync-skills.js --write`; `--check` проверяет их соответствие без
записи. Импортированные справочники сохраняют исходное оформление и исключены
из общих style-lint правил; их синтаксис и работоспособность проверяются отдельно.

Пути к скриптам определяются относительно прочитанного справочника; рабочий каталог
и входные/выходные данные принадлежат проекту-потребителю. Для веб-инструментов
корень задаётся `ECC_1C_PROJECT_ROOT` или текущим каталогом проекта. Состояние браузера
и снимки ошибок хранятся в `<project>/.scratch/1c-web-client/`.

Зависимости подключаются по необходимости: Python и `lxml` для XML-инструментов,
Pillow для сетки изображения, `psutil` для просмотра веб-окружения; Node/Playwright
для импортированного браузерного движка. Для сборки и работы с ИБ нужна выбранная
платформа 1С и её реальные команды. Ничего из этого не устанавливается при чтении
навыка. Методы БСП проверяются по встроенной версии.

`web-publish`, `web-stop` и `web-unpublish` сохранены как ручные процедуры.
Их исполняемые скрипты исключены: исходные варианты автоматически загружали сервер,
задавали широкую публикацию либо управляли процессами. Настройку конкретного сервера
следует выполнять отдельной задачей с определённой областью изменений и откатом.
Данные веб-пользователя не извлекаются из MCP-конфигурации.

Старые `web-test/.browser-session.json` и `web-test/error-shot.png` из архива
исключены из набора: это состояние и снимок рабочего сеанса, а не ресурсы навыка.
Новые данные сеансов хранятся в игнорируемом рабочем каталоге потребителя.

## Что перенесено и что осталось проектным

Архив содержит 421 запись и 89 исходных навыков. 81 техническая операция сохранена
в общем инструментарии. Шесть навыков диагностики, требований, Git, организации
файлов и проверки переработаны в текущие правила и рабочие процессы ECC.
`planfix-tracker` и `mcp-setup` не стали обязательными зависимостями разработки 1С.
Карта происхождения: [source-map.json](source-map.json).

Суффикс `_ЕМК`, комментарии `// ++ ИИ`, фиксированные числа агентов/повторов и
согласование перед каждой правкой не перенесены в общую политику. Их можно явно
принять в конкретном проекте. Существующие Git/docs/test процессы ECC сохраняются.

В исходном архиве мало собственно языковых паттернов BSL. Этот слой дополнен
по [первичным источникам](../../skills/1c-bsl-patterns/references/sources.md).
Версия платформы и совместимость всегда проверяются для целевого проекта.

## Границы проверки

Проверки оформления, регистрации, синтаксиса скриптов и искусственных XML-примеров
подтверждают только перечисленные свойства набора. Они не подтверждают компиляцию
или выполнение в установленной 1С, работу MCP, применимость к конкретной
конфигурации, корректность бизнес-расчётов либо обновление ИБ.
Исходники, загруженная конфигурация и обновлённая ИБ — отдельные результаты.

Исходные заголовки кода сохранены. Архив не содержит отдельного файла лицензии;
происхождение импортированных ресурсов указано явно, лицензия MIT им дополнительно
не присваивалась.
