# Работа с Database в проекте

Database — общий каталог инструкций и скиллов для Codex. Начни с [ветки database](https://github.com/Gakulllka/ai-database/tree/database) и скилла `database-onboarding`.

- Для текущей задачи используй подходящие установленные скиллы. Если их нет или цель существенно изменилась, получи свежий коммит ветки `database`, сверься с `common/catalog.json` и прочитай `pack.json` нужной темы. Бери инструкции и ресурсы из одного коммита.
- При понятной задаче выбери пакет самостоятельно. Если один недостающий факт меняет выбор, задай один короткий вопрос.
- В подключённом проекте при существенной смене цели скачай целиком подходящую тему и добавь пакет командой `node common/tools/database.mjs setup --project "<абсолютный путь>" --pack <id>` из корня Database. Проверь результат через `node common/tools/database.mjs check --project "<абсолютный путь>"`. Ранее подключённые пакеты и проектные правила сохраняются.
- Основные файлы скиллов лежат в `.database/library/<pack>/skills/`. Папка `.agents/skills/` содержит маршруты для Codex. Роли выбранных пакетов находятся в `.codex/agents/`.
- Основной ИИ работает как оркестратор: делегирует ограниченные подзадачи, выбирает доступную модель и глубину рассуждения, проверяет результаты и интегрирует изменения. Для небольшой задачи достаточно одного исполнителя. Читай [порядок оркестрации](.database/library/common/docs/agents/orchestration.md); учитывай фактические ограничения хоста и сохраняй пользовательские настройки ролей.
- Если скилл не сработал или темы нет, исследуй задачу, проверь решение на примере и сохрани только то, что пригодится в другом проекте. Выбери существующий пакет. Для темы без подходящего пакета добавь папку верхнего уровня с `pack.json` и запись в каталоге.
- Публикуй в `database` только проверенные изменения в согласованных пользователем границах. Используй общедоступные или синтетические данные, сохраняй публичную историю и проверяй результат на GitHub.
