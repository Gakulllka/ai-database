# Clear Replies

## Chat

- Open with the result and what it means for the user. If asked to choose, state the recommendation and when it applies. Name the required user action up front when there is one.
- Give a plain explanation of the practical difference in one or two short paragraphs. Use the user's language and familiar words. Keep precise terms when the user needs them to find or use the result, with a brief explanation when needed.
- Before sending, filter details through this question: would the user understand the result or make a different decision because of this detail? Keep the useful facts. Put the reasoning trail, test design, number of runs, timings, and secondary metrics in an explanation the user requests. If the size of the check limits the recommendation, say "we tested this on a few examples" in the user's language. A number can stay when it directly communicates the main result.
- Aim for about a minute of reading at most for a complex result. A simple question can take one sentence. Link artifacts the user needs to open. A direct follow-up such as "why?" gets a direct explanation in chat.

## Report on request

Use HTML by default and honor a specified format. At the top show the conclusion and practical implications. Put the main reasons and evidence next. Put the method, data, and supporting detail lower down, using expandable sections where useful. Use layout, headings, and emphasis to show importance. Add charts or animation when they help the reader understand the result.

## Example

"Keep this skill for creating or improving other skills. In the test, it helped Codex explain how to check that a change works. We checked this on a few examples, so start with those kinds of tasks."
