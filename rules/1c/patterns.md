# 1C / BSL Patterns

> This file extends [common/patterns.md](../common/patterns.md) with 1C-specific content.

## Existing mechanisms and replacement

- Перед добавлением логики найди действующую реализацию по именам и предметному смыслу: общий модуль, обработчик, подписка, форма, расширение, запрос и доступный механизм БСП. Проследи вызовы и точки входа.
- Сначала оцени применимый типовой механизм и его публичный интерфейс в фактической версии. Пример из ИТС или другой конфигурации требует проверки контекста, доступности и контракта; наличие похожего кода не делает его подходящим автоматически.
- Если реализация уже существует, исправляй или расширяй ответственный участок вместо добавления второй реализации рядом. Перед созданием нового метода укажи, почему найденный механизм не подходит и какие места будут его вызывать.
- При замене собственной логики проверь оставшийся старый код и повторные вызовы. Устаревший участок удаляй или переводь на новый путь только после проверки зависимостей, включая подписки, XML форм, перехватчики и динамические вызовы. Сохранённый адаптер совместимости должен иметь явное назначение.
- Не удаляй типовой или посторонний код ради общей очистки. Не оставляй закомментированные копии и варианты `Новый`/`Исправленный` как способ исправить исходную процедуру; историю хранит система контроля версий.
- Если поиск был ограничен частью исходников, обозначь область поиска. Не объявляй механизм отсутствующим во всей конфигурации по неполной выборке.
- Новые бизнес-правила, формулы, исключения и критерии результата задаёт пользователь. ИИ предлагает технические варианты и уточняет существенную неизвестность; правдоподобное предположение не становится требованием.

## Execution context

- Для управляемой формы выбирай `&НаКлиенте`, `&НаСервере` или `&НаСервереБезКонтекста` по реально нужным данным.
- Серверный метод без контекста формы получает необходимые значения параметрами. Он не должен обращаться к реквизитам формы.
- У общих модулей проверяй свойства доступности и экспорт; директивы формы не заменяют настройки модуля.
- Бизнес-проверки и работу с ИБ размещай на стороне, где соответствующий API доступен.

## Queries and transactions

- Значения передавай через параметры запроса и `УстановитьПараметр`. Динамические имена объектов и полей проверяй по метаданным и разрешённому набору.
- Границы периода, округление и повторный запуск выводи из бизнес-правила; даты и суммы примера не становятся константами.
- Выясняй, кто владеет транзакцией: платформа, вызывающий код или текущая процедура. Не коммить и не отменяй чужой этап работы.
- При собственной явной транзакции связывай успешное завершение с фиксацией, исключение — с откатом и передачей ошибки выше.
- Для конкурентного чтения с последующей записью учитывай режим блокировок и защищаемый набор данных. Одна проверка в форме не обеспечивает целостность при параллельных сеансах.

## Configuration lifecycle

Сохраняй совместимость существующих обработчиков, поддержки типового решения и БСП.
Различай изменение файлов, загрузку конфигурации и обновление конфигурации ИБ.
Доступ к выгрузке не подтверждает свежесть или состояние подключённой базы.
